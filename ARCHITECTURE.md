# Catapult Chaos — архитектура

## Назначение

Браузерная 2D-игра на **Vite + TypeScript (strict) + Matter.js**. Мир рисуется только Canvas 2D, меню/HUD — HTML/CSS, звуки синтезируются через Web Audio API. Внешних спрайтов, аудиофайлов, backend и сетевых зависимостей нет.

Этот документ — входная точка для разработчика и AI-агента. Перед изменением прочитай также `AGENTS.md` и профильный skill в `.Codex/skills/gameplay/`.

## Запуск и проверка

```bash
npm install
npm run dev
npm run typecheck
npm run build
```

`npm run build` уже включает `tsc --noEmit`. `vite.config.ts` содержит `base: './'`, его нельзя заменять на `'/'`: сборка должна работать на GitHub Pages в подпапке.

## Поток одного кадра

1. `core/Engine.ts` накапливает реальное время и запускает физику фиксированными шагами `1000 / 60` мс. Длинный кадр ограничен, hitstop временно останавливает симуляцию.
2. `Game.fixedUpdate` выполняет отложенные действия игрового времени, обновляет гаджеты и способности, затем вызывает `PhysicsWorld.step`.
3. `PhysicsWorld` ограничивает скорость до и после `Matter.Engine.update`, принимает столкновения Matter и публикует их в `EventBus` с оценкой импульса.
4. `Game` применяет урон, запускает цепные реакции и проверяет `SettlingDetector`.
5. `Renderer` рисует мир через `Camera`. `HUD` обновляется независимо от Canvas.

Состояния: `LEVEL_SELECT → AIMING → FLYING → SETTLING → WON/LOST`, плюс `PAUSED`. Следующий кот выдаётся только после покоя сцены или таймаута.

## Карта модулей

```text
src/
├── core/                 # Цикл, камера, ввод, события, звук, частицы, сохранения, аналитика
├── physics/              # Matter.js и определение стабилизации
├── entities/
│   ├── types.ts          # GameBody, CatDefinition, GadgetInstance и метаданные
│   ├── CatRegistry.ts
│   ├── BlockRegistry.ts
│   ├── GadgetRegistry.ts
│   ├── cats/             # Один файл = один кот
│   └── gadgets/          # Один файл = один тип гаджета
├── gameplay/             # Рогатка, цели, состояния
├── levels/               # LevelData и декларативные уровни
├── rendering/            # Canvas, процедурные коты, debug overlay
├── ui/HUD.ts             # DOM-меню и HUD
├── Game.ts               # Composition root и правила одного хода
├── constants.ts          # Общие игровые параметры

```

### Метаданные тел

Любое игровое тело создаётся через `attachMetadata` и имеет тип `GameBody`. В `body.game` находятся `entityId`, `kind`, `typeId`, HP, порог импульса и размеры для процедурного рендера. Не добавляй отдельные словари для данных, которые принадлежат одному телу.

### События

`core/EventBus.ts` содержит полную карту полезной нагрузки `GameEvents`. Новые межсистемные уведомления добавляются сначала туда. Внутри одного простого модуля шина не нужна. Не создавай глушённые события «на будущее».

Важные события: `physics:collision-start`, `block:destroyed`, `target:destroyed`, `gadget:goal`, `gadget:bonus`, `gadget:laser-hit`, `gadget:rope-cut`, `channel:changed`, `cat:ability`, `audio:play`, `game:hitstop`.

### Реестры

- `CatRegistry`: конфиг внешности/физики и хуки способности.
- `BlockRegistry`: плотность, HP, порог урона, цвет, очки, признак взрывчатки.
- `GadgetRegistry`: фабрика, создающая тела и поведение гаджета.

Загрузчик уровня не содержит `switch` по котам или гаджетам. Новый тип регистрируется один раз в `cats/index.ts`, `gadgets/index.ts` или `registrations.ts`.

## Обязательные инварианты физики

- **Spawn grace:** урон отключён первые 400 мс после загрузки уровня.
- **Velocity cap:** максимальная скорость — `PHYSICS.maxSpeed`; задавать скорости через `PhysicsWorld.setVelocityCapped`.
- **Settling:** 0,8 с ниже порогов скорости, 7 с после первого удара или абсолютные 12 с.
- **Порталы:** per-body cooldown 250 мс и выход за пределы сенсора по нормали.
- **TNT:** удаление блока и взрыв разделены задержкой 80–120 мс через игровой scheduler, не через `setTimeout`.
- **Goal zone:** объект должен находиться внутри 0,8 с; повреждение доставляемого объекта не отключается.
- Все gameplay-таймеры должны использовать `Game.schedule`, чтобы pause/hitstop не рассинхронизировали логику.

## Рецепт: добавить кота

1. Создай `src/entities/cats/NewCat.ts`.
2. Экспортируй `CatDefinition`: уникальные `id`, имя/подсказку, цвета, радиус, массу, упругость, трение.
3. Реализуй `onAbilityActivate(ctx)`. Для продолжительного эффекта вызови `ctx.setAbilityDuration(ms)` и добавь `onAbilityUpdate`/`onAbilityEnd`.
4. Если способность разрешена после удара, установи `allowAbilityAfterCollision: true`. По умолчанию клик работает только до первого не-сенсорного столкновения.
5. Зарегистрируй определение в `src/entities/cats/index.ts`.
6. При необходимости добавь визуальный акцент в `CatRenderer.drawVariant`. Базовые эмоции и тело рисовать заново не нужно.
7. Добавь `id` в `queue` уровня, затем проверь способность до удара, после удара и при pause/hitstop.

Нельзя обращаться из кота к DOM/HUD. Нужны скорость/тела — используй `ctx.physics`; события/очки/попапы — `ctx.events`.

## Рецепт: добавить гаджет

1. Добавь отдельный интерфейс в discriminated union `GadgetSpawnConfig` (`src/levels/schema.ts`).
2. Создай фабрику `src/entities/gadgets/NewGadget.ts` через `defineGadgetFactory('type', ...)`: так конфиг остаётся строго типизированным.
3. Создай Matter-тела, вызови `attachMetadata` с `kind: 'gadget'` и добавь их в `ctx.physics`; constraints добавляй через `addConstraint`.
4. Верни `GadgetInstance`: `id`, `type`, `bodies`, при необходимости `update`, `render`, `onCollisionStart`, `onCollisionEnd`, `onLaserHit`.
5. Зарегистрируй фабрику в `src/entities/gadgets/index.ts`.
6. Добавь декларативный spawn на уровень. Для каналов используй `ctx.channels`, не собственную глобальную карту состояний.

Сенсоры не должны наносить урон от касания. Для телепортов/одиночных срабатываний предусмотри per-body cooldown или флаг. Удали тело из физики после одноразового сбора, как в `BonusFish`.

## Каталог доступных механик и гаджетов

Все координаты и размеры заданы в мировых пикселях, углы — в градусах. Общие поля каждого spawn: `id`, `type`, `x`, `y`. Необязательные параметры имеют значения по умолчанию в фабрике гаджета.

| `type` | Параметры конфигурации | Канал | Физика и взаимодействия |
|---|---|---|---|
| `trampoline` | `width`, `height`, `angle` | нет | Статическое тело; при касании меняет скорость динамического тела вдоль нормали через velocity cap. |
| `portal` | обязательный `pairId`; `width`, `height`, `angle` | нет | Два взаимно связанных сенсора. Переносит динамическое тело с поворотом скорости; cooldown 250 мс и безопасный выход за сенсор. |
| `goal_zone` | `targetId`, `width`, `height`, `angle` | нет | Сенсор доставки сейфа; требует непрерывного удержания 0,8 с. Разрушение сейфа приводит к поражению. |
| `bonus_fish` | `radius` | нет | Одноразовый статический сенсор бонуса, удаляется после касания динамическим телом. |
| `button` | обязательный `channelId`; `mode: once \| toggle`, `impulseThreshold`, `width`, `height` | **триггер** | Статический корпус. Срабатывает от удара динамического тела с импульсом не ниже порога (24 по умолчанию); `once` фиксирует сигнал, `toggle` переключает его с задержкой от дребезга 260 мс. |
| `pressure_plate` | обязательный `channelId`; `minMass`, `width`, `height` | **триггер** | Твёрдая платформа и сенсор над ней. Каждый тик суммирует массу пересекающихся динамических тел; сигнал держится только при `totalMass >= minMass` (15 по умолчанию). Визуальный прогиб и полоска показывают вес. |
| `door` | `channelId`, `invertSignal`; `width`, `height`, `angle`, `openOffset`, `moveSpeed` | приёмник | Статическая преграда плавно перемещается через `Body.setPosition`. `openOffset` — смещение в мировых осях, `moveSpeed` — пиксели за шаг 60 Гц. Без канала закрыта; при потере сигнала закрывается. |
| `trapdoor` | `channelId`, `invertSignal`; `width`, `height`, `angle`, `hinge: left \| right`, `material: wood \| metal` | приёмник | Заблокированная статическая балка с шарниром на краю. Сигнал один раз снимает статичность, балка падает под гравитацией на `Matter.Constraint`. Без канала закрыта; обратного автоматического закрытия нет. |
| `fan` | `channelId`, `invertSignal`; `width`, `height`, `angle`, `strength` | приёмник; без канала включён | Прямоугольный сенсор прикладывает постоянную силу вдоль `angle`: одинаковая сила слабее разгоняет тяжёлые тела. Лопасти и полосы потока рисуются на Canvas. |
| `gravity_zone` | `channelId`, `invertSignal`; `width`, `height`, `gravityScale` | приёмник; без канала включена | Компенсирует мировую гравитацию и задаёт собственную: `0` — невесомость, отрицательное значение — подъём. Есть демпфирование и velocity cap. Не накладывай несколько таких зон друг на друга. |
| `seesaw` | `width`, `height`, `angle`, `pivotOffset`, `maxTilt` | нет | Динамическая балка на жёстком центральном/смещённом шарнире. Угол ограничен относительно начального (`maxTilt`, по умолчанию ±40°), поэтому доска не вращается свободно. |
| `rope` | обязательный `anchor`; `targetBlockId` **или** `cargo: stone \| tnt \| treasure_box`; `cargoWidth`, `cargoHeight` | нет, разрезается лазером | Жёсткий `Matter.Constraint` между мировым якорем и существующим телом либо встроенным грузом. Кот, коснувшийся сенсора верёвки, или луч лазера разрывают constraint; груз падает. Сенсор следует за грузом. |
| `laser` | `channelId`, `invertSignal`; `angle`, `maxLength` | приёмник; без канала включён | Каждый тик raycast идёт до ближайшей грани плотного тела. Обычные сенсоры игнорируются, сенсор `rope` — нет. **Стекло полностью пропускает луч** и не разбивается. TNT исчезает со взрывом через игровые 150 мс, верёвка разрывается, `vacuum` уничтожается; камень, дерево, статика, двери и другие плотные тела блокируют луч с искрами. |

### Каналы и проектирование головоломок

- `gameplay/ChannelSystem.ts` хранит состояния источников по `channelId`. Несколько кнопок/плит на одном канале объединяются логическим **OR**. Изменение публикуется как `channel:changed` в общий `EventBus`.
- Приёмник читает `receiverSignal(channelId, invertSignal, defaultWithoutChannel)`. Для подключённого `invertSignal: true` он включён, пока канал неактивен, и выключается при сигнале. Без `channelId` инверсия не применяется: используется естественное состояние типа (вентилятор/лазер включены, дверь/люк закрыты).
- У триггеров и приёмников есть цветная лампа. `red`, `blue`, `green`, `yellow` имеют фиксированные цвета, другие имена получают детерминированный цвет. Пунктирные связи видны первые 4 секунды и при debug по `D`.
- `LevelLoader.load` вызывает `ChannelSystem.reset` до создания сущностей, поэтому рестарт не сохраняет ни нажатия, ни состояния OR-каналов.
- Комбинируй одну цепочку за раз: триггер → преграду/опасность → физический путь кота. Например: плита удерживает дверь открытой, пока на ней лежит камень; кнопка роняет люк и одновременно выключает вентилятор через инверсию; ящик задерживает лазер, а после его разрушения луч перерезает верёвку и поджигает следующий объект.
- Проверяй альтернативный путь и экстремумы массы: обычный кот имеет массу 15, наковальня после способности значительно тяжелее. Для удерживаемых плит оставь место под блок, а для дверей — безопасный `openOffset`, не ведущий в другие тела.
- `sandbox-gadgets` — изолированный полигон со всеми механиками и бесконечной сменой котов. Он открывается отдельной кнопкой меню, не входит в `LEVELS`, прогресс кампании и последовательность `next`.

## Рецепт: создать уровень

1. Скопируй наиболее похожий `src/levels/levelNN.ts`.
2. Заполни `LevelData`: уникальные `id` всех сущностей, рогатку, очередь, пороги звёзд, цели, блоки, цели-враги и гаджеты.
3. Экспортируй уровень и добавь его в массив `LEVELS` в `src/levels/index.ts`.
4. Координаты — мировые пиксели, размер стандартного мира 1920×1080, углы — градусы. Пол обычно имеет центр `y: 1020`, высоту 80.
5. Для доставки свяжи `goals[].targetId/zoneId`, `gadgets[].targetId` и `targets[].id`.
6. Для порталов задай обоим одинаковый pair-link через взаимные `pairId`.
7. Проверь победу, поражение, 1/2/3 звезды, рыбку и завершение хода без бесконечного дрожания.

## Прогресс и Яндекс Игры

`IStorageAdapter` асинхронен: `load(): Promise<GameProgress>` и `save(progress): Promise<void>`. Для SDK создай `YandexStorageAdapter`, реализующий этот интерфейс, и передай его в `new Game(canvas, hud, adapter)`. Игровые системы не должны вызывать `localStorage` или SDK напрямую. Сохраняются лучший счёт, максимум звёзд и собранная рыбка отдельно для каждого уровня.

## Аналитика и сложность уровней

Сниппет Яндекс.Метрики (счётчик `114661698`) подключён в `index.html`. Все игровые события отправляет `core/Analytics.ts` через единственную функцию `track(event, params)`; игровые системы не вызывают `ym` напрямую. Подробная настройка целей, отчётов и воронок в интерфейсе Метрики — в `ANALYTICS.md`.

| Цель | Когда отправляется | Ключевые параметры |
|---|---|---|
| `app_open` | после загрузки прогресса | `returning`, `levels_cleared`, `total_stars` |
| `level_start` | игрок начал/перезапустил уровень | `level`, `from`, `attempt`, `first_try`, `replay`, `stars_before` |
| `level_win` | победа | `level`, `attempt`, `first_try`, `replay`, `stars`, `stars_up`, `clear`, `score`, `duration_s`, `cats_total`, `cats_launched`, `cats_zero`, `zero_pct`, `unused_cats`, `ability_pct`, `bonus_fish`, `touch_*` |
| `level_fail` | поражение | те же агрегаты, плюс `reason` (`out_of_cats` / `treasure_lost`), `targets_left`, `goals_left` |
| `level_quit` | рестарт или выход в меню без победы/поражения | `reason` (`restart` / `menu`), `score`, `duration_s`, `cats_*`, `targets_left`, `goals_left` |
| `cat_shot` | завершённый ход кота | `shot`, `cat`, `ability_used`, `ability_timing`, `ability_delay_ms`, `points`, `zero`, `collided`, `ability_miss`, `kittens` |

`cat_shot` считается один раз на ход: `points` — прирост очков от запуска до стабилизации, котята Splitter входят в тот же ход (`kittens`). `zero_pct` и `ability_pct` считаются по завершённым ходам; `unused_cats` — коты, оставшиеся в очереди. `level_win` дополнительно содержит `stars_up` (стало больше звёзд, чем было) и `clear` (какой по счёту раз уровень пройден), поэтому повторные заходы за звёздами видны отдельно от первого прохождения.

`touch_<type>` — факт 0/1 взаимодействия активного кота с гаджетом, который есть на уровне; для `goal_zone` и `bonus_fish` отметка ставится по событиям доставки/бонуса. Это дешёвый способ понять, пользовался ли игрок порталом/батутом, без инструментации каждого гаджета.

Номер попытки хранится в памяти сессии и сбрасывается после победы, поэтому `attempt = 2` и `first_try = 0` означают «уровень не пройден с первого раза», а `replay = 1` — заход на уже пройденный уровень. Dev-сервер цели не отправляет (чтобы отладочные прогоны не портили отчёт); проверять можно production-сборкой или `?ymdebug` в адресе. Sandbox-полигон в статистику не попадает. Ограничения Метрики: 200 целей на счётчик, 400 онлайн-целей за визит, одна и та же цель не чаще раза в секунду; параметры `reachGoal` видны в отчётах только для заведённых целей. Контрфактический импакт способности не измеряется — отчёты показывают корреляцию `ability_used` с `points`.

## Debug и ручная приёмка

- `D`: хитбоксы, векторы скорости, FPS/число тел.
- `R`: мгновенный рестарт.
- `C`: обзор/слежение, `M`: звук, `Esc`: пауза, `Space`: способность.
- Проверить мышь и тач, высокий DPR, узкий экран, паузу во время TNT/магнита, повторный вход в портал и перезапуск после победы.

Перед завершением изменения обязательны `npm run typecheck` и `npm run build`.
