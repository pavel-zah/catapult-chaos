# Аналитика Catapult Chaos

Игра отправляет события в Яндекс.Метрику (счётчик `114661698`) через `src/core/Analytics.ts`. Единственная точка отправки — функция `track(event, params)`: она нормализует значения, добавляет параметр `event` и вызывает `ym(COUNTER_ID, 'reachGoal', ...)`. В dev-режиме события не уходят, чтобы отладочные прогоны не портили статистику; принудительно включить отправку можно параметром `?ymdebug` в адресе.

## 1. Что отправляется

| Цель | Когда | Основные параметры |
|---|---|---|
| `app_open` | после загрузки прогресса | `returning`, `levels_cleared`, `total_stars` |
| `level_start` | старт/рестарт уровня | `level`, `from`, `attempt`, `first_try`, `replay`, `stars_before` |
| `level_win` | победа | `level`, `attempt`, `first_try`, `replay`, `stars`, `stars_up`, `clear`, `score`, `duration_s`, `cats_total`, `cats_launched`, `cats_zero`, `zero_pct`, `unused_cats`, `ability_pct`, `bonus_fish`, `touch_*` |
| `level_fail` | поражение | `level`, `attempt`, `first_try`, `replay`, `reason`, `score`, `duration_s`, `cats_*`, `zero_pct`, `ability_pct`, `targets_left`, `goals_left`, `touch_*` |
| `level_quit` | рестарт/выход в меню с незавершённого уровня | `level`, `reason`, `score`, `duration_s`, `cats_*`, `targets_left`, `goals_left` |
| `cat_shot` | завершённый ход кота | `shot`, `cat`, `ability_used`, `ability_timing`, `ability_delay_ms`, `points`, `zero`, `collided`, `ability_miss`, `kittens` |

Пояснения:

- `reason` у `level_fail`: `out_of_cats` — закончились коты, `treasure_lost` — разбит сейф.
- `reason` у `level_quit`: `restart` — рестарт, `menu` — выход в меню.
- `from` у `level_start`: `menu`, `next`, `restart`.
- `stars_before` — лучший результат до попытки; `replay = 1`, если уровень уже был пройден.
- `stars_up = 1`, если после победы звёзд стало больше, чем было.
- `clear` — какой по счёту раз уровень пройден (первое прохождение = 1).
- `points` в `cat_shot` — прирост очков за ход; бонус за неиспользованных котов входит только в `score` события `level_win`.
- `zero_pct` и `ability_pct` считаются по завершённым ходам. `unused_cats` — коты, оставшиеся в очереди. Ноль очков за ход — это не всегда бесполезный ход (кот мог подготовить падение), но как быстрый индикатор «выстрел в молоко» метрика работает.
- `ability_timing`: `none`, `before_hit`, `after_hit`. `ability_miss = 1`, если способность не использована и ход дал 0 очков; это эвристика «возможность, похоже, упущена».
- `kittens` — сколько детей создал Splitter в этом ходе.
- `touch_<type>` — 0/1: взаимодействовал ли игрок с гаджетом этого типа на уровне.

## 2. Создать цели в Метрике

Это нужно сделать **до** первого тестового прогона: параметры `reachGoal` попадают в отчёты только для заведённых целей.

1. Открой `metrika.yandex.ru` и выбери счётчик **114661698**.
2. В левом меню нажми **«Цели»**.
3. Нажми **«Добавить цель»**.
4. Выбери тип **«Целевое событие»**.
5. Заполни:
   - **«Название»** — например, «Старт уровня»;
   - **«Условие»** — **«совпадает»**;
   - **«Идентификатор»** — строго из таблицы ниже.
6. Нажми **«Добавить цель»**.
7. Повтори для всех шести целей.

| Название | Идентификатор |
|---|---|
| Открытие игры | `app_open` |
| Старт уровня | `level_start` |
| Уровень пройден | `level_win` |
| Уровень провален | `level_fail` |
| Выход с уровня | `level_quit` |
| Ход кота | `cat_shot` |

Если цели `level_start`, `level_win`, `level_fail`, `level_quit` уже созданы — не создавай их повторно, просто проверь идентификаторы. Новые в этой версии: `app_open` и `cat_shot`.

## 3. Проверить, что события уходят

1. Открой production-сборку (или `npm run build && npm run preview`).
2. Добавь к адресу `?_ym_debug=2` — внизу страницы появится панель отладки Метрики. На dev-сервере дополнительно нужен `?ymdebug`, иначе наш код не отправит событие:
   `http://localhost:5173/?ymdebug&_ym_debug=2`.
3. Начни уровень, сделай ход, выиграй или проиграй.
4. В панели отладки на вкладках **Events** и **Console** должны появиться `level_start`, `cat_shot`, `level_win` / `level_fail`.
5. Через несколько минут проверь **«Отчёты» → «Конверсии»**.

Если событий нет:

- цель не создана в интерфейсе;
- открыта dev-сборка без `?ymdebug`;
- сработал блокировщик рекламы;
- используется другой счётчик.

## 4. Отчёты под конкретные вопросы

Все отчёты доступны через **«Отчёты» → «Содержание»**. В левой панели отчёта параметры можно добавлять как группировки. Числовые параметры Метрика считает как сумму и среднее — добавь их в метрики отчёта.

### Где отсеиваются игроки

Быстрый вариант:

- **«Отчёты» → «Содержание» → «Параметры событий»**;
- группировка `event`, затем `level`;
- фильтр `event = level_start`;
- смотри метрику **«Посетители»**, а не «Достижения», иначе рестарты раздуют цифры.

Падение числа посетителей от `level01` к `level02` и далее — это и есть отсев.

Наглядный вариант — воронка, см. раздел 5.

### Сложность уровня

- **«Отчёты» → «Конверсии»** → цель `level_win` → группировка `level`;
- сравни с количеством `level_start` по тому же уровню;
- отдельно: «Параметры событий» → `event = level_fail`, группировка `level` + `reason`, метрики: средние `score`, `zero_pct`, `targets_left`, `goals_left`.

### Провал с первой попытки и «закончились коты»

- «Параметры событий» → `event = level_fail` + `reason = out_of_cats` + `first_try = 1` + `replay = 0`;
- группировка `level`;
- метрики: количество, средний `score`, средний `zero_pct`, средний `targets_left`.

`replay = 0` важен: после победы счётчик попыток сбрасывается, и повторный заход тоже будет `first_try = 1`, но это уже не первое знакомство с уровнем.

### Звёзды

- «Параметры событий» → `event = level_win`;
- группировка `level` + `stars`;
- количество достижений покажет распределение 1/2/3 звезды;
- `stars_up = 1` — сколько побед улучшили результат.

### Перепроходят ли за звёздами

- «Параметры событий» → `event = level_start`;
- группировка `level` + `replay`;
- `replay = 1` — доля повторных заходов;
- воронка: `level_start` с `replay=1` → `level_win` с `stars_up=1`.

### Коты и способности

- «Параметры событий» → `event = cat_shot`;
- группировка `cat` + `ability_used`;
- метрики: количество и средний `points`;
- так видно, у какого кота способность повышает результат, а у какого нет;
- фильтр `ability_miss = 1` покажет ходы, где способность не использована и очков ноль;
- группировка по `ability_timing` покажет, насколько поздно игроки её нажимают.

### Процент использованных способностей по уровням

- «Параметры событий» → `event = level_win` и отдельно `event = level_fail`;
- группировка `level`;
- метрика — средний `ability_pct`.

### Понятность механик

- «Параметры событий» → `event = level_fail` / `level_win`;
- группировка `level`;
- смотри средние `touch_portal`, `touch_trampoline`, `touch_goal_zone` и т.д.

Если на уровне 3 с порталом `touch_portal` близок к 0, а провалов много — игроки либо не доходят до портала, либо не понимают его. Дальше смотри вебвизор по этим сессиям.

### Количество очков

- «Параметры событий» → `event = level_win` / `level_fail`;
- группировка `level`;
- добавь `score` как числовую метрику (среднее/сумма).

## 5. Воронка «где отваливаются»

1. **«Отчёты»** → внизу **«Создать отчёт»** → **«Воронка»**.
2. Название: «Прохождение кампании».
3. Окно воронки: неограниченное или 30–60 минут.
4. Шаги — через **«Добавить условие» → «Параметры события»**:

| Шаг | Условия |
|---|---|
| Открыл игру | `event = app_open` |
| Старт 1 уровня | `event = level_start` **И** `level = level01` |
| Прошёл 1 уровень | `event = level_win` **И** `level = level01` |
| Старт 2 уровня | `event = level_start` **И** `level = level02` |
| Прошёл 2 уровень | `event = level_win` **И** `level = level02` |
| … | … |

По умолчанию условия внутри шага объединены через **ИЛИ** — переключи на **И**. В одном шаге можно использовать до трёх условий. Максимум шагов в воронке — 10; для четырёх уровней хватает девяти шагов. Если уровней станет больше, раздели воронку на две или строй её только по `level_start`.

В настройках конверсии выбери **«Конверсия от предыдущего шага»** — тогда сразу видно, на каком переходе наибольшая потеря.

Важно: шаги воронки должны произойти в рамках одного визита. Если игрок закрыл игру и вернулся позже, цепочка может не засчитаться. Поэтому для отсева дублируй воронку обычным отчётом по `level_start` с метрикой «Посетители».

## 6. Дашборд

В **«Дашбордах»** можно собрать виджеты:

- старты и победы по уровням;
- распределение звёзд;
- причины провалов;
- средний `zero_pct`;
- средний `ability_pct`;
- `touch_*` по уровням.

## 7. Ограничения

- До **200 целей** на счётчик — используется 6.
- До **400 достижений онлайн-целей за визит**. `cat_shot` — самое частое событие; при обычной игре это десятки событий. При экстремальном гриндинге лимит может упереться.
- Одна и та же цель фиксируется **не чаще раза в секунду**. Ходы длятся дольше; редкие потери при спаме рестарта не критичны.
- До **8 КБ** на параметры события и до **512 параметров за визит** — payload’ы маленькие.
- Цель должна быть создана **до** отправки, иначе параметры могут не попасть в отчёт.
- Блокировщики рекламы режут часть данных — цифры относительные, не абсолютные.
- Закрытие вкладки не отправляет `level_quit`; для отсева используй воронку и старты уровней.
- Контрфактический импакт способности не измеряется: отчёты показывают корреляцию `ability_used` с `points`, а не «что было бы, если бы игрок нажал».

## 8. Что проверить вручную после изменений

1. `npm run typecheck` и `npm run build`.
2. Открыть игру с `?ymdebug` (на dev) или production-сборку.
3. Пройти уровень: в консоли должны быть `level_start`, несколько `cat_shot`, `level_win`.
4. Намеренно проиграть: `level_fail` с `reason=out_of_cats`.
5. Нажать рестарт: `level_quit` с `reason=restart`, затем новый `level_start`.
6. Сыграть повторно на уже пройденном уровне: `level_start` с `replay=1`, при улучшении — `level_win` с `stars_up=1`.
